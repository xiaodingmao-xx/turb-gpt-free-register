# 账号页与注册元数据改进设计

## 背景与目标

本次需求包含账号页显示、邮箱池取件地址、账号选择反馈、套餐网络信息和注册 OTP 隔离五部分：

1. “注册密码”列中的“已设置”、密码显示/隐藏和复制密码功能纵向排列。
2. 通用 API 邮箱池导入的 `code_url` 不在账号列表中直接展示，只提供“复制取件地址”。
3. 账号页持续显示当前已选账号数量，并覆盖分页、全选和取消选择场景。
4. 套餐栏在出口地区下方显示注册时记录的出口 IP。
5. 注册阶段已经使用的邮箱 OTP 不得被后续设置密码阶段再次提交；取码接口返回旧验证码时必须等待/触发新验证码。

本设计不处理用户消息中附带的第三方登录验证码；该验证码与项目代码没有关联，也不写入项目文件、日志或测试数据。

## 当前实现核对

- 前端入口是 `webui/templates/index.html`，账号列表由 `renderAccounts()` 渲染，密码单元格由 `_registrationPasswordCell()` 渲染。
- 后端账号列表入口是 `webui/app.py:/api/accounts`，紧凑字段由 `_compact_account_for_list()` 组装。
- 账号敏感值当前通过 `webui/app.py:/api/accounts/<id>/secret` 按需读取，已支持 `registration_password`，但还没有 `pickup_address`。
- 通用 API 邮箱池字段名是 `code_url`，数据查询入口是 `db.get_generic_api_email_by_email()`。
- 当前账号列表会把 `pickup_address` 直接返回给前端并完整渲染；这与“只复制、不直接显示”的要求不符。
- `ACCOUNT_SELECTED` 和 `accountsSelectedHintV2` 已实现基础计数，需要补齐回归覆盖，避免后续列表刷新或分页改动破坏计数。
- 套餐栏已有 `plan_eligibility_*` 和 `plan_exit_*` 展示逻辑，但注册保存路径没有统一保存 `registration_ip`。
- Roxy 注册流程在注册 OTP 阶段和设置密码 OTP 阶段分别调用 `wait_for_otp()`；通用 API 在缺少邮件时间戳时可能返回接口缓存的旧验证码。

## 方案

采用“列表脱敏 + 按需读取 + 注册元数据显式保存 + OTP 新旧码隔离”的方案。

### 1. 账号列表中的敏感字段

账号列表响应不再携带通用 API 的完整 `code_url`。后端只返回布尔字段 `pickup_address_available`：

- 账号来源为 `generic_api` 且账号记录或通用 API 邮箱池存在 `code_url` 时为 `true`。
- 其他邮箱来源统一为 `false`，不在本次需求中显示取件地址。

新增 secret 字段 `pickup_address`。读取时仅允许从 `generic_api` 账号的已保存 `pickup_address` 或邮箱池 `code_url` 解析，其他来源返回空值。前端点击“复制取件地址”后才请求该字段，并复用现有剪贴板降级逻辑；完整地址不进入列表 DOM，也不出现在普通账号列表 JSON 中。

### 2. 注册密码列布局与复制

保留现有注册密码按需读取方式，不把明文密码加入账号列表。密码单元格改为纵向布局，固定展示以下顺序：

1. `已设置` 状态。
2. 掩码密码和“显示密码”操作；显示密码通过 `registration_password` secret 请求获取，重复点击可恢复掩码。
3. “复制密码”操作；复制时读取同一个 secret 字段，不要求先显示明文。

“密码未知”状态仍不显示复制/显示按钮。按钮请求期间禁用，空值和接口异常只显示提示，不把密码写入日志或响应错误文本。

### 3. 账号选择数量

沿用 `ACCOUNT_SELECTED` 作为跨分页选择集合，`accountsSelectedHintV2` 作为唯一显示入口。补充以下行为约束：

- 单行勾选/取消后立即更新数量。
- 当前页全选/取消全选只增删当前页 ID，不影响其他页已选 ID。
- 刷新列表后仍按 ID 恢复勾选状态，数量与集合大小一致。
- 无选择时批量操作继续禁用。

不新增后端选中状态，避免把短暂的前端选择同步到持久化数据。

### 4. 注册 IP 到套餐栏

账号记录新增可选元数据 `registration_ip`，历史账号没有该字段时前端隐藏该行。保存时按注册驱动的实际出口获取：

- `main.py` 的 HTTP 注册路径使用 `BrowserSession.exit_geo.ip`。
- Browser Use、RoxyBrowser、CloakBrowser 路径在当前浏览器会话内执行一次轻量出口 IP 查询，取当前浏览器实际出口；失败时不阻断注册，只记录为空。
- `core/account_export.py` 将该字段传给 `core.db.insert_account()`，保持 JSON 账号记录和批次归档的元数据一致。

账号列表紧凑响应增加 `registration_ip`（仅有值时返回）。`_planRegionDetail()` 在“出口地区”下面渲染“注册 IP”，与套餐查询得到的 `plan_exit_ip` 分开，避免把注册网络和后续查套餐网络混为一谈。

### 5. 注册 OTP 与设置密码 OTP 隔离

注册流程只在内存中保留本次成功提交的 `registration_otp`，不持久化、不写入日志。调用设置密码流程时把它作为“禁止重复使用的验证码”传入。

设置密码阶段的取码流程：

1. 请求邮箱 OTP 时携带排除集合，至少包含注册阶段已提交的验证码。
2. 通用 API 客户端在结构化响应有时间戳或只有纯文本时，都不得返回排除集合中的验证码。
3. 若当前页面仍要求 OTP 且取码接口持续返回旧码，先不填写旧码；触发一次“重新发送验证码”，更新时间边界后重新轮询。
4. 新验证码通过后才允许清空输入框、填写并提交。
5. 设置密码自身的 OTP 重试仍保留现有最大尝试次数和失败处理。

为保持兼容，`email_provider.wait_for_otp()` 增加可选的排除验证码参数；没有排除需求的现有调用不改变行为。通用 API 客户端负责严格应用该参数，其他来源继续使用现有时间戳过滤，必要时沿用现有重发逻辑。

## 数据流

```text
通用 API 邮箱池(code_url)
        │
        ├─ 账号列表：只生成 pickup_address_available
        │                  │
        │                  └─ 点击复制 ──> secret(pickup_address) ──> clipboard
        │
注册驱动 ──> registration_ip ──> save_account_data ──> account record
                                                │
                                                └─> /api/accounts compact ──> 套餐栏

注册 OTP ──> registration_otp(仅内存)
                    │
                    └─> 设置密码 OTP 排除集合 ──> 新验证码 ──> 提交
```

## 错误处理与安全边界

- 取件地址或密码读取失败只返回通用错误提示；不在前端错误消息、Flask JSON 响应或日志中输出完整敏感值。
- `pickup_address` 只对 `generic_api` 来源开放，不能通过修改 URL 参数读取其他来源地址。
- 注册 IP 探测属于非关键补充信息；探测失败不使注册失败，历史或不支持的驱动显示为空。
- OTP 新码等待超时沿用当前注册任务失败和邮箱回收策略，禁止以旧验证码“兜底提交”。
- 普通账号列表接口保持紧凑响应，不恢复 Token、邮箱密码或其他现有敏感字段泄露。

## 测试设计

### WebUI 与数据接口

- 紧凑账号列表只返回 `pickup_address_available`，不返回完整 `pickup_address`。
- `generic_api` 账号可通过 secret 接口读取 `code_url`；非 `generic_api` 账号读取为空。
- 模板不再把 `r.pickup_address` 直接渲染到账号行，只渲染复制按钮。
- 注册密码模板包含纵向布局、“显示密码”和“复制密码”操作；复制操作不要求先显示密码。
- 账号选择单选、当前页全选、取消全选和刷新后的数量保持一致。
- 套餐栏包含注册 IP 标签，缺失注册 IP 时不渲染空行。

### 注册与 OTP

- 通用 API 结构化响应带旧时间戳时被 `after_ts` 和排除集合共同过滤。
- 通用 API 纯文本响应返回与注册阶段相同的验证码时被排除，不会直接返回。
- Roxy 设置密码流程首次取到注册 OTP 时不调用 `_type_otp()`，会重发并等待下一码；新码才允许提交。
- 没有注册阶段排除验证码的独立“设置密码”任务保持原有流程。
- 注册 IP 能从 HTTP 会话和浏览器驱动的元数据传递到账号记录；探测异常时账号仍能保存。

## 不在本次范围内

- 不重构现有账号/邮箱池持久化格式，不迁移历史数据；新增字段均为可选。
- 不为 Outlook、Cloudflare 或其他邮箱来源新增取件地址展示。
- 不改变套餐查询使用的出口 IP 字段，只补充注册时出口 IP。
- 不改变密码生成规则、设置密码队列并发策略或现有登录/注册页面选择器。
